# installer/ — the MSIX packages

Two ways to get AwazSetu onto a Windows machine. Both run the same application,
entirely offline, with no Python, FFmpeg, Ollama or model download.

| | `.msix` (here) | `.zip` (the Drive folder) |
|---|---|---|
| Start Menu entry, proper uninstall | yes | no |
| Deployable by IT through Intune | yes | no |
| Needs administrator rights **once** | yes | **no** |
| Needs a trust decision | yes | no |
| Works on a fully locked-down laptop | no | yes |

If you are evaluating AwazSetu, the `.zip` is less trouble. The `.msix` exists
for the case where it has to look and behave like an installed Windows
application.

## Install

Right-click **`Install.ps1`** and choose *Run with PowerShell*. It trusts the
signing certificate (one administrator prompt), then installs the package.

Then start **AwazSetu** from the Start Menu. A browser tab opens at
`http://127.0.0.1:5000`.

To remove it: **`Uninstall.ps1`**. Add `-PurgeData` to delete your processed
videos too, and `-RemoveCert` to stop trusting the certificate.

## Why there is a certificate at all

Windows will not install an MSIX whose signature it does not trust. This is not
a setting; there is no developer-mode switch that turns it off. A commercial
code-signing certificate is issued to a registered legal entity and costs money
per year, which is not something a hackathon team has.

So the package is signed with a certificate generated on the build machine, and
`Install.ps1` places it in **`LocalMachine\TrustedPeople`** — deliberately not in
`Root`. `TrustedPeople` means "accept packages signed by exactly this
certificate". `Root` would mean "this certificate may vouch for anything on this
machine", which is far more than is being asked for.

The certificate is visible before you accept it: `Install.ps1` prints its
subject, expiry and thumbprint. `Uninstall.ps1 -RemoveCert` takes it back out.

## What the package does to the machine

- Installs to `C:\Program Files\WindowsApps\FluentFusion.AwazSetu_...`,
  read-only, managed by Windows.
- Writes your data to `%LOCALAPPDATA%\AwazSetu` — processed videos, uploads and
  settings. Nothing else, anywhere.
- No services, no scheduled tasks, no registry keys of its own, no network
  access. The only listener is a local web server on `127.0.0.1`, which is how
  the browser reaches the application.

The fifteen pre-processed videos ship inside the package and are served from
there, read-only. Anything you add afterwards lands in `%LOCALAPPDATA%`. Both
appear together in one library.

## Building these

```bat
python scripts\build_msix.py test              REM ~2s, proves the whole chain
python scripts\build_msix.py lite --stage      REM builds dist\awazsetu-lite\ first
python scripts\build_msix.py both --stage
```

Needs `makeappx.exe` and `signtool.exe` from the Windows 10/11 SDK, and
`csc.exe` from the .NET Framework that ships with Windows. The build finds all
three itself.

**Disk:** MSIX cannot compress model weights that are already compressed, so a
10.7 GB payload makes a 10.7 GB package — and `makeappx` needs the staged folder
and the output at the same time. Budget roughly **2.5× the payload** in free
space, on the same volume as `dist\`.

The signing key is created on first build and kept in `installer/cert/`, which is
git-ignored. It is not in the package, and the package contains no credentials of
any kind.
